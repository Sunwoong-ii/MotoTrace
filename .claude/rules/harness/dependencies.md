# 의존성

새로 작성하거나 수정하는 코드에 적용한다. 기존 구조가 이 규칙과 다르면 기존 구조를 따르고, 구조 변경은 제안만 한다.

## 모듈 경계

- 다른 모듈의 구현체에 직접 의존하지 않는다. 공개 인터페이스(프로토콜, Interface 모듈)에만 의존한다.
- 구현체 연결은 조립 지점(앱 타겟, DI 컨테이너)에서만 한다.
- 의존 방향은 프로젝트가 정한 방향을 따르고, 순환 의존을 만들지 않는다.
- Feature끼리 직접 의존하지 않는다. 화면 전환이나 데이터 전달은 인터페이스나 상위 조립 계층을 거친다.
- 필요한 의존성은 생성자로 주입한다. 싱글턴이나 전역 상태를 새로 만들거나 직접 참조하지 않는다.

## 외부 의존성

- 새 외부 라이브러리는 임의로 추가하지 않는다. 표준 라이브러리나 Apple 프레임워크로 해결할 수 있는지 먼저 보고, 필요하면 이유와 함께 제안한다.
- 외부 의존성(Third-party framework/library)이 비즈니스 로직이나 Feature에 직접 노출되지 않도록 필요 시 추상화한다. 특히 교체 가능성, 테스트 대체, 구현 세부사항 은닉이 필요한 경우 Protocol/Adapter 등의 경계를 둔다.
- 외부 라이브러리 타입을 모듈의 공개 API(프로토콜 시그니처, 공개 모델)에 노출하지 않는다.
- 위치·모션·카메라 같은 시스템 서비스도 테스트 대체가 필요하면 같은 경계를 둔다.
- 외부 의존성의 버전 변경(업데이트 포함)은 요청받았을 때만 한다.

## 과한 추상화 금지

- 구현이 하나뿐이고 교체·테스트 대체·은닉이 필요 없으면 프로토콜이나 래퍼를 만들지 않는다.
- 새 경계를 만들기 전에 프로젝트에 이미 있는 인터페이스나 어댑터를 재사용한다.
