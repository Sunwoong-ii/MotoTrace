# 테스트

## 작성

- 기존 테스트의 프레임워크(XCTest / Swift Testing), 파일 구조, 네이밍을 따른다. 한 파일 안에서 프레임워크를 섞지 않는다.
- Given-When-Then 구조로 쓰고, 테스트 하나는 동작 하나만 검증한다.
- 테스트 이름에 동작, 조건, 기대 결과가 드러나게 한다.
- 내부 구현이 아니라 공개된 동작을 검증한다. 리팩터만으로 깨지는 테스트를 만들지 않는다.
- UI 테스트는 접근성 식별자로 요소를 찾는다. 표시 텍스트나 좌표에 의존하지 않는다.

## 격리

- 네트워크, 현재 시각, 난수, 위치·센서, 파일 시스템, UserDefaults 같은 외부 상태에 직접 의존하지 않는다. 프로토콜 기반 fake/mock을 주입한다.
- 프로덕션 코드에 테스트 전용 분기를 넣지 않는다. 의존성 주입으로 바꿔 끼울 수 있게 만든다.
- 비동기 코드는 async 테스트에서 `await`, `fulfillment(of:)`, `confirmation`으로 기다린다. `sleep`이나 고정 대기로 타이밍을 맞추지 않는다.

## 수정

- 버그를 고칠 때는 먼저 실패하는 테스트로 재현하고, 수정 후 통과를 확인한다.
- 테스트를 통과시키려고 assertion을 약화하거나, 기대값을 구현에 맞춰 바꾸거나, 테스트를 삭제·skip하지 않는다. 테스트가 틀렸다고 판단되면 근거와 함께 보고한다.
